# Status

**Inputs**: spec markers, open change records, inbox, records, git.
**Writes**: none.
**Result**: an answer to the question, then the views below, then next eligible actions.

Status is generated by `.prdkit/scripts/bash/status.sh` (`--json` for the derived form), never
written as prose in the spec or docs. Its handwritten inputs are change State and Acceptance,
`specs/inbox.md` and `specs/records.md`; it reads local files and git only. For a checked `ref=`
reason it verifies the referenced entry in `specs/authority.md` and reports the reference, not the
quote. A broken reference fails status with the records line number.

The adoption summary separates recorded install version and observed spec layout.
`Compaction due` (JSON `compaction`) appears at ten closed changes logged since the latest
`compaction` line, in either log order.

Answer the owner's question first, in plain words, with the title next to every ID. Then:

1. **Outcome progress**: original goal, intended architecture, next milestone, last evidenced
   advance (or none/unknown), critical path, lane allocation and next-task rationale from the
   parent's checkpoint. Name timebox/investment exhaustion, displaced lanes and repeated completed
   changes without an advance before listing test or PR totals. Reconcile newer PR context when
   available; the local helper only projects recorded State fields and the no-progress count/limit,
   not evidence validity or prose deadlines. Missing fields stay unknown, malformed/duplicate ones
   invalid; reaching the count limit says `reassess`, never grants authority or claims a failed test.
   Read `### Outcome checkpoint` within State.
   Children link their parent; standalone changes without a checkpoint have no outcome row.
   A parent referenced by a child stays visible as unknown even if its record/checkpoint is missing.
2. **True now**: requirements, qualities and parts with maturity, `planned` and unenforced items.
   For UI questions, read the optional L1 `specs/design.md` if present.
3. **In flight**: open changes from every registered worktree, with where each lives, step,
   age, attempts and what each waits on; reviewed records merged without closing; unmerged branches.
4. **Live**: the latest `DEPLOY` record per app and environment (`rev=none`: nothing deployed);
   merged but not deployed.
5. **Holds and waivers** with owner, full scope and end condition; past-due holds still apply,
   expired waivers do not. Read the referenced quote only when its wording is needed.
6. **Owner queue**: unanswered owner questions with age. Report recorded answers and direction
   awaiting agent processing separately; a filled answer is not proof of incorporation.
7. **Longest pole**: the item that most delays the current goal, and what it waits on. The helper's
   age/attempt heuristic is a candidate, not a computed critical path; reconcile it with the programme.

Merged, live and validated stay distinct. Keep what the helper observed apart from your reading of
it; unknown stays unknown. A closed/logged PR is not proof of runtime acceptance. Non-gating
observations live on that PR; local status does not fetch them or infer a PASS from record deletion.
Next actions are recommendations, never execution permission.
